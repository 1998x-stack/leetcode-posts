LEETCODE 49 / MEDIUM / ARRAYS-HASHING

字母异位词分组

为每个单词生成规范化签名：签名相同，就进入同一个桶。

Mediumhash-lookup可视化题解

LeetCode 官方原题 ↗

01 · 先弄清楚题目要做什么

给定字符串数组，把互为字母异位词的单词放在同一组。例：eat、tea、tan、ate、nat、bat 可以分为 [eat, tea, ate]、[tan, nat]、[bat]。组间顺序不重要。

先抓住核心：为每个单词生成规范化签名：签名相同，就进入同一个桶。

02 · 从朴素方法出发

逐个单词与已有组的代表词比较是否互为异位词，可能反复扫描字符。更直接的办法是计算与字符顺序无关的频次签名，再用哈希表聚合。

优化不是背模板，而是识别输入中可复用的信息：能否记录已经见过的内容？能否维护一个规模受控的候选集合？能否安全地排除不可能的状态？

03 · 状态与不变量

key(word) 是 26 个字母的频次元组。遍历任意输入前缀后，groups[key] 恰好保存此前所有具有相同字符频次的单词。频次向量相同，当且仅当两个单词互为异位词。

05 · 为什么算法正确

对任意单词，签名的第 i 个分量就是第 i 个字母的出现次数。两个字符串互为异位词，当且仅当所有字符频次相同，也就是签名相等。因此按签名分桶既不会错误合并，也不会拆散同一异位词组。每个输入单词只进入一个桶。

正确性来自状态不变量：每次更新都保持它，终止时它恰好推出题目要求的结果。

06 · Python 参考实现

实现与上面的状态定义及证明一一对应。

from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: list[str]) -> list[list[str]]:
        groups = defaultdict(list)
        for word in strs:
            count = [0] * 26
            for char in word:
                count[ord(char) - ord("a")] += 1
            groups[tuple(count)].append(word)
        return list(groups.values())

复杂度分析

设 k 为单词数，L 为总字符数。时间 O(L + 26k) = O(L+k)。频次签名与分组结构占 O(26k+L) = O(k+L) 空间。

07 · 反例与边界检查

按长度分组不够，eat 与 tan 长度相同但不是异位词；只比较字符集合也不够，aab 与 abb 的集合相同但频次不同。列表不可哈希，签名必须转成 tuple。
