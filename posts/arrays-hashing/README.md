# 数组与哈希表

从连续数组的索引访问出发，学习如何用哈希结构记录已扫描信息，再用前后缀累计减少重复计算。

## 学习顺序
1. **集合判重** — LeetCode 217：先判断是否见过，再决定是否加入。
2. **哈希补数查找** — LeetCode 1：把配对搜索改写为一次字典查询。
3. **前后缀累计** — LeetCode 238：把当前位置以外的贡献拆成左右两部分。

## 这一专题要回答的问题
- 只需判断成员关系时，为什么 set 比 dict 更贴切？
- 需要返回下标时，为什么哈希表要保存 value → index？
- 辅助结构记录的是整个数组，还是“当前元素之前的前缀”？
- 期望 O(1) 的哈希操作与最坏复杂度有什么区别？
- 输出数组是否计入额外空间？输入是否被原地修改？

## 掌握标准
能从扫描前缀定义不变量；能解释 Two Sum 的先查后存；能处理 Product Except Self 中的零；能准确区分输入、辅助空间与输出空间。
