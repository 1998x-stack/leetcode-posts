LeetCode 322 · 零钱兑换

把 11 元拆成更小的问题：每个金额的最优解从哪里来？

中等 Medium16 分钟Dynamic Programming

LeetCode 官方原题 ↗返回全部题解 ↗

01 · 题意与约束

coins = [1,2,5]、amount = 11，最少需要 3 枚：5+5+1。若 coins=[2]、amount=3，返回 -1；amount=0 时返回 0。

02 · 从朴素思路走向优化

递归尝试每一枚硬币，会反复计算相同的剩余金额。动态规划把每个金额只计算一次。

假设最后放入的硬币面额为 c，则前面先凑出 x-c 元，再加一枚硬币：dp[x]=min(dp[x-c]+1)。枚举所有 c<=x，按金额递增计算，因此依赖已就绪，硬币也可重复使用。

03 · 核心状态与不变量

每一步都必须保持

dp[x] 表示凑出金额 x 所需的最少硬币数。dp[0]=0；其他金额初始化为不可达哨兵 amount+1。计算 x 时只依赖更小金额 x-coin。

05 · 为什么算法正确？

任意非零金额的合法组合都包含某一枚最后加入的硬币 c。去掉它，剩余金额为 x-c；若剩余组合不是最优，就能替换成更少硬币的组合，改进原方案，矛盾。枚举每个 c 因而覆盖某个最优方案；dp[0]=0 是归纳起点。若最终仍为哨兵，则金额不可达。

06 · Python 参考实现

下面是完整的 LeetCode 兼容实现。树节点由评测环境提供；LRU 的链表节点在解法中显式定义。

class Solution:
    def coinChange(self, coins: list[int], amount: int) -> int:
        unreachable = amount + 1
        dp = [unreachable] * (amount + 1)
        dp[0] = 0
        for current in range(1, amount + 1):
            for coin in coins:
                if coin <= current:
                    dp[current] = min(dp[current], dp[current - coin] + 1)
        return -1 if dp[amount] == unreachable else dp[amount]

时间与空间复杂度

设 A 为 amount、C 为硬币种类数。时间 O(A×C)，额外空间 O(A)。返回值是整数，不另有随输入增长的输出结构。

07 · 一个边界条件，足以改变答案

不可达状态不能初始化为 0，否则不存在的组合会被当成零枚硬币。用 amount+1 作哨兵；每枚硬币至少为 1，任何可达方案最多用 amount 枚。注意本题是无限次使用硬币。
