LeetCode 3 · 无重复字符的最长子串

一个窗口、两个边界：为什么只需要线性扫描？

01 · 题意与直觉

输入 s = "abcabcbb"，最长无重复的连续片段可以是 "abc"，长度为 3。注意题目要求的是连续子串，不是可以跳过字符的子序列。

先想一想：为什么不直接暴力枚举？

朴素办法是枚举每个起点，再向右扩展直到遇到重复，最坏需要 O(n²) 次比较。已经检查过的无重复区间信息被反复丢弃。

02 · 先说清什么永远不变

循环 / 递归不变量

每轮处理完下标 right 后，闭区间 [left, right] 中所有字符互不重复；left 只会向右移动，且窗口是以 right 为结尾的最长合法窗口。

记录每个字符上一次出现的下标 last_seen[c]。若它在当前窗口内出现（位置 ≥ left），将 left 跳到其后；若上一次出现的位置早于 left，就不必移动。更新最优长度 right-left+1。

04 · 为什么不会漏掉答案？

归纳看：加入一个新字符时，窗口中至多只有这个字符可能和旧元素冲突，因为旧窗口原本无重复。若冲突，所有不晚于旧位置的起点均无法构成以 right 结尾的合法子串，所以跳过它们不会漏掉更长答案。left 不回退，故始终合法且候选完整。

请区分算法的不变量和恰好出现在某个样例中的现象：前者必须对所有合法输入成立，后者只能帮助建立直觉。

05 · Python 参考实现

下面使用 LeetCode 的 class Solution 接口。源代码同时保存在仓库的 solution.py 中，并由确定性测试覆盖主要边界。

class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last_seen: dict[str, int] = {}
        left = best = 0
        for right, ch in enumerate(s):
            if ch in last_seen and last_seen[ch] >= left:
                left = last_seen[ch] + 1
            last_seen[ch] = right
            best = max(best, right - left + 1)
        return best

时间与空间复杂度

维度分析
时间 / 空间时间 O(n)：right 遍历一次，哈希表操作期望 O(1)；额外空间 O(min(n, |Σ|)) 保存最后位置，|Σ| 是可用字符种类。
算法范围上述结论以官方输入语义与 Python 常规操作成本为前提；本地演示不代表 LeetCode 排名或运行时百分位。

06 · 一张图记住易错点

对于 "abba"，处理最后一个 a 时，旧 a 位于窗口左侧。错误写法 left=last_seen[a]+1 会从 2 回退到 1，造成含两个 b 的假窗口；正确写法是取 max(left,旧位置+1)。
