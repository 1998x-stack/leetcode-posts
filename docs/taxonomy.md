# LeetCode 知识分类与知识图谱规范

> 本文件是分类设计的权威说明。机器可读的领域注册表位于 \`content/domains.json\`，当前可访问的算法专题位于 \`content/categories.json\`，横向标签词表位于 \`content/facets.json\`，文章归属和实际标签位于 \`content/posts.json\`。

## 1. 设计目标

本仓库不是按 LeetCode 标签堆放题目的题库，而是一个以算法知识为主线、以解题模式为核心、以具体题目为载体的可视化知识库。分类体系需要同时满足：

- **能教会迁移**：读者看到新题时，能识别问题模型、选择算法并说明正确性。
- **边界稳定**：分类依据算法机制和知识结构，不跟随单道题或流行标签频繁变化。
- **允许交叉**：一篇文章只有一个主归属，但可以关联多个数据结构、技巧、问题形态和证明工具。
- **适合渐进扩展**：尚无文章的方向列入路线图，不创建空文章、不制造虚假内容数量。
- **机器可验证**：分类 slug、主归属、横向标签、学习阶段和关联关系均可由构建脚本检查。

## 2. 五层纵向结构

| 层级 | 名称 | 回答的问题 | 示例 |
|---|---|---|---|
| L0 | 学习阶段 | 现在应该学到什么程度？ | 基础建立、核心模式、进阶技巧 |
| L1 | 知识领域 | 这部分知识属于哪块算法版图？ | 线性模式、树与递归、图论 |
| L2 | 算法专题 | 主要使用哪一类算法机制？ | 双指针、滑动窗口、回溯 |
| L3 | 问题模式 | 具体是哪种可复用的问题结构？ | 对向指针、可变窗口、连通分量 |
| L4 | 具体题目 | 用哪道题把机制讲清楚？ | LeetCode 3、11、15、46、200 |

L0 是学习进度轴，不是分类父节点；L1–L4 构成内容组织主干。L3 的命名应描述**可迁移的问题模式**，而不是题目名称或某个代码片段。

## 3. L1 知识领域与 L2 专题规划

领域注册表按顺序定义在 \`content/domains.json\`。每个领域包含当前已启用的 L2 专题（由 \`categories.json\` 中的 \`domain\` 字段归属）和未来计划建设的专题。路线图中的条目不是已发布分类，也不生成空文章页面。

| L1 知识领域 | L2 算法专题（规划范围） |
|---|---|
| 线性数据结构与字符串 | 数组与哈希表、字符串、链表、栈/队列/双端队列、堆与优先队列 |
| 线性扫描与区间技巧 | 双指针、滑动窗口、前缀和与差分、二分查找、排序与区间、单调栈与单调队列 |
| 树、递归与分治 | 二叉树、二叉搜索树、字典树、分治算法 |
| 图论与网格 | 图与网格遍历、并查集、拓扑排序、最短路径 |
| 搜索与组合枚举 | 回溯（排列、组合、子集、约束搜索与剪枝） |
| 动态规划与贪心优化 | 动态规划、贪心算法 |
| 数学与位运算 | 位运算、数论、模运算与组合计数 |
| 高级数据结构与区间查询 | 树状数组、线段树及区间查询结构 |

这不是要求一次性建立所有分类。只有当某个方向出现足够的题目、清晰的共同机制和独立的教学价值时，才将它从路线图提升为正式专题。

## 4. 当前 L2 → L3 映射

| L1 领域 | 当前 L2 专题 | L3 问题模式 |
|---|---|---|
| 线性扫描与区间技巧 | 双指针 | 对向双指针、排序后枚举与去重、同向双指针 |
| 线性扫描与区间技巧 | 滑动窗口 | 可变长窗口、窗口计数、定长窗口 |
| 搜索与组合枚举 | 回溯与搜索 | 排列枚举、剪枝与约束、组合枚举、子集枚举 |
| 图论与网格 | 图与网格 | 网格建模与邻接关系、图遍历与访问状态、连通分量与区域计数 |

现有文章保持原路径和稳定 slug，不为分类升级移动已发布文章。

## 5. 单一主归属规则

每篇文章必须且只能有一个 \`category\` 和一个 \`topic\`：

1. 选择**证明核心机制**所属的专题，而不是选择代码里出现次数最多的数据结构。
2. 如果多种技巧都重要，选择决定算法正确性或复杂度改善的那一个作为主专题。
3. 其他技巧通过横向 facets 表达；不要复制文章到多个分类目录。
4. 一篇题解可以比较多种解法，但主归属只反映文章的教学主线。
5. 如果两个专题边界长期模糊，先调整定义与范围，不要立即增加新分类。

判例：
- LeetCode 46 的核心是选择、递归、撤销，主归属为回溯；DFS 是横向技巧。
- LeetCode 200 的核心是连通分量遍历，主归属为图与网格；DFS 是横向技巧。
- LeetCode 3 的核心是维护合法连续区间，主归属为滑动窗口；哈希表是辅助结构。
- LeetCode 15 的核心是排序后固定一个数并收缩双指针，主归属为双指针；排序和去重是横向技巧。

## 6. 横向 facets：让知识可以多对多连接

\`content/facets.json\` 定义受控词表。每篇文章在 \`content/posts.json\` 的 \`facets\` 字段中填写：

| 字段 | 说明 | 例子 |
|---|---|---|
| \`structures\` | 使用或建模的数据结构 | array、hash-map、grid |
| \`techniques\` | 可复用的算法技术 | two-pointers、depth-first-search |
| \`problem_shapes\` | 题目抽象后的问题形态 | k-sum-triplets、connected-component-count |
| \`reasoning\` | 关键不变量或正确性论证 | candidate-elimination、state-restoration |
| \`prerequisites\` | 阅读本文前需要掌握的知识 | recursion-basics、dfs-basics |
| \`learning_stage\` | 本文适合的学习阶段 | foundation、core、advanced |

不要把所有内容都塞进 \`tags\`。自由标签只用于别名、搜索词或补充描述；稳定的知识关系必须使用 facets。每个 facet 应有明确语义，避免同义词重复注册（例如同时创建 \`dfs\`、\`depth-first\`、\`depth-first-search\`）。

## 7. 学习路径不是分类

分类回答“它是什么”，学习路径回答“先学什么、再学什么”。路径保存在 \`content/reading_paths.json\`：

- 前置知识 → 核心机制 → 变体 → 综合题；
- 一条路径应有明确的学习目标和顺序；
- 不要仅仅因为两篇文章共享一个宽泛标签，就把它们排成前后关系；
- 路径中的文章必须已发布，且每一步都应有学习理由。

后续可基于 \`prerequisites\` 建立依赖图，再人工审核拓扑顺序；不能仅凭标签自动推断教学顺序。

## 8. 相关推荐与知识图谱

相关推荐按以下优先级计算，而不是只按一级分类或关键词相似度：

1. 同一学习路径中的相邻文章；
2. 相同 L3 问题模式；
3. 相同问题形态或关键算法技巧；
4. 相同证明机制；
5. 前置知识或数据结构的补充关联。

仅共享“数组”“DFS”等宽泛标签，不足以成为强相关推荐。每条推荐应说明关系类型，例如“补充基础”“同一技巧”“相似问题模型”或“证明方法迁移”。

## 9. 新专题晋升条件

路线图专题升级为正式分类前，至少满足：

- 有 3 篇以上计划题目，且能说明共同边界；
- 与现有专题的主机制不同，不是已有专题的别名；
- 至少能拆出 2 个有教学价值的 L3 模式；
- 有可复用的核心不变量、状态定义或正确性论证；
- 能设计连续学习路径，而不是只为了某一道题建分类。

若只有 1–2 道题，优先放入现有专题的 L3 模式或 facets，不急于创建新 L2。

## 10. URL、slug 与兼容性

- 已发布文章路径 \`posts/<category>/<slug>/\` 永久稳定；不要因分类重构搬动文章。
- category/topic/facet/domain 的 slug 使用小写 kebab-case，发布后不随意重命名。
- 更正标题时保留 slug；确需迁移时提供旧 URL 重定向。
- 仅当前启用的类别写入 \`categories.json\` 并生成页面；路线图只在知识地图显示为“规划中”。
- 更新分类时同步检查 \`AGENTS.md\`、README、Skill、构建校验、搜索索引、相关推荐和学习路径。

## 12. 首批基础专题的 L2 → L3 → 题目映射

本轮将三个规划方向提升为正式专题。每个专题先用三道题建立不同层次的模式，而不是把一篇题解当作整个知识领域。

| L2 专题 | L3 问题模式 | 代表题 | 学习目标 |
|---|---|---|---|
| 数组与哈希表 | 集合判重 | #217 Contains Duplicate | 用已扫描集合维护前缀信息 |
| 数组与哈希表 | 哈希补数查找 | #1 Two Sum | 一次扫描中将配对搜索降为期望 O(1) 查询 |
| 数组与哈希表 | 前后缀累计 | #238 Product of Array Except Self | 将“除自身外”拆成左右两侧贡献 |
| 二分查找 | 精确查找 | #704 Binary Search | 明确闭区间和终止条件 |
| 二分查找 | 边界查找 | #34 Find First and Last Position | 用 lower_bound / upper_bound 找分界 |
| 二分查找 | 旋转数组 | #33 Search in Rotated Sorted Array | 识别至少一半有序并安全排除另一半 |
| 二叉树 | 递归定义与树高 | #104 Maximum Depth | 基例、递归关系和返回值含义 |
| 二叉树 | 层序遍历 | #102 Binary Tree Level Order Traversal | 用队列长度隔离当前层与下一层 |
| 二叉树 | 后序信息汇总 | #543 Diameter of Binary Tree | 子树先返回高度，当前节点更新全局路径 |

### 专题边界

- **数组与哈希表**关注序列数据如何被索引、映射、去重和累计；滑动窗口、双指针仍属于它们各自的算法机制专题。
- **二分查找**的核心不是“数组中间取一个数”，而是存在一个可证明的单调判定边界。旋转数组题要求先证明哪一半有序。
- **二叉树**按节点递归结构组织。DFS/BFS 是遍历策略，不能替代“树高”“层序分组”“后序汇总”等问题模式。

### 每个专题的最低掌握标准

1. 能从输入约束判断是否存在哈希查找、有序单调性或树递归结构。
2. 能写出状态不变量或递归函数的精确定义。
3. 能解释每次更新为什么安全、循环为什么终止。
4. 能区分辅助空间、递归栈和输出空间。
5. 能用至少一个反例解释常见错误写法。
