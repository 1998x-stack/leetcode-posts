# 题解编写准则 · Skill v2

## 先推理，后写页面
每篇先完成 problem brief：官方约束、暴力基线、模式前提、状态/不变量/递推、正确性证明、复杂度、反例、测试设计。没有证明就不要先画图。

## 正确性
证明必须覆盖初始化、状态维护、终止和答案提取。解释为什么没有漏解，也没有重复或错误解。DP 解释状态含义和转移完备性；单调栈解释弹出时为何得到第一个满足条件的元素；BFS 解释队列顺序和层边界；数据结构设计解释映射与链表一致性。

## 教学表达
面向大学生/研究生，但默认读者刚接触该模式。先用具体例子，再给术语；段落短，符号先定义，反例具体。避免只讲口诀、只贴代码或堆砌复杂术语。

## 视觉
三幅 SVG 必须承担不同任务：cover 展示核心机制，trace 展示真实状态，pitfall 展示反例。值、索引、指针、层级、栈序、链表方向必须和代码一致。禁止套用同一张封面。

## 代码与测试
标准库 Python、LeetCode 兼容接口。说明输入是否改变。测试包含官方语义、边界、对抗样例和小范围差分比较。对 LRU 等结构检查内部不变量；不要把运行样例当作完整证明。

## 发布
draft 经过单测、SVG 审计、构建、静态校验和 Chromium 多尺寸 QA 后才可发布。PR 的 CI 必须通过；PDF 校验与 Pages 部署分别记录。成功合并不等于已部署。
